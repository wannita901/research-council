Phase 2 · Architecture & Design

Architecture & the Cross-Vendor Debate Protocol

Drafted 2026-06-04 · Design doc — no code yet · Provider-agnostic, minimal core

The novelty lives in two places: (1) a debate protocol where different vendors' models critique each other, and (2) executable verification as the tie-breaker so the "best" answer is decided by tests passing, not rhetoric. Everything else is deliberately thin and replaceable.

Design principles
  • Provider-agnostic core. A role is bound to a provider at runtime; the orchestrator never imports a vendor SDK directly.
  • Ground truth > opinion. Where a claim is checkable (code compiles, tests pass, metric improves), the verifier overrides the debate.
  • Minimal repo. Thin custom orchestrator over raw SDKs + typed message contracts. No heavy agent framework in the core (LangGraph/AutoGen are fallbacks, not dependencies).
  • Human-in-the-loop by default. Every stage can pause for approval. We do not market "fully autonomous."
  • Everything is logged. Full debate transcripts + artifacts are first-class — they are the eval data later.

2. Provider Abstraction Layer

One interface, three adapters. The rest of the system speaks only this interface, so swapping or adding a vendor is a single adapter.

class LLMProvider(Protocol):
    name: str                      # "openai" | "claude" | "gemini"
    model: str
    async def complete(
        self, messages: list[Message],
        tools: list[Tool] | None = None,
        schema: dict | None = None, # forces structured output
    ) -> Response                  # .text, .tool_calls, .usage, .cost

Responsibilities kept here (not leaked upward): retries/backoff, prompt caching, token+cost accounting, structured-output coercion, rate limiting.

3. Agent Layer — 3 symmetric peers, one per vendor

The panel is 3 symmetric peer agents (one model per vendor: OpenAI, Claude, Gemini). There is no fixed "the proposer" / "the critic" — every peer proposes and critiques. Each peer first researches independently (with retrieval-tool access), proposes a grounded candidate, then critiques the other two. Judging is a panel function, not a dedicated agent.

Peer ×3 (proposer + critic)

Each vendor: researches independently → proposes a candidate → critiques the other two's candidates (soundness / novelty / feasibility), citing evidence or requesting verification.

Judge = panel vote + human

Peers score all candidates with authorship anonymized; the verifier signal weights the scores into a recommendation; the human confirms the final pick. Not a 4th agent.

Verifier (tool, not LLM)

Runs the sandbox / checks. Returns ground-truth signals that outweigh any peer's opinion wherever a claim is checkable.

Vendor binding

Which model fills each of the 3 vendor seats is asked at run start (overridable by flags/config). See Decisions Q1.

4. The Debate Protocol core contribution

A debate is a config: the 3 vendor seats, how many rounds, and the termination rule. The flow has an explicit independent-research phase before the peers convene:

0 INTAKE          human asks a question / proposes a topic
        │
1 RESEARCH        the 3 peers investigate IN PARALLEL, independently
  (parallel)      each uses retrieval tools → forms its own grounded view
        │
2 PROPOSE         each peer puts forward one candidate (gap / idea / plan / patch)
        │
3 CROSS-CRITIQUE  every peer critiques the other two's candidates
        │
4 REBUT / REVISE  authors defend or revise in response
        │
5 VERIFY          sandbox runs checkable claims → ground-truth signal
        │
6 JUDGE           anonymized panel vote, verifier-weighted → recommendation;
                  human confirms the final pick
   (loop 3→6 until a termination rule fires)

Termination rules (pick per stage)

  1. Verification-gated (preferred when artifact is executable): stop when a candidate passes the objective check (tests green / metric beats baseline). Rhetoric cannot override a failing build.
  2. Consensus: stop when critics raise no new substantive objection for a full round (measured, not vibes — track distinct objection set).
  3. Panel vote + max rounds: fallback for non-executable stages (e.g., gap-framing). Anonymized peer vote produces a recommendation; human confirms. Cap rounds to bound cost.
Bias control (design rationale)

Peers are symmetric, so self-preference bias (LLMs favouring their own / same-family output) is the main threat at the judge step. Mitigations baked into the protocol: (a) anonymize authorship in critique and scoring prompts (strip "this was written by X"); (b) prefer the verifier signal over peer opinion whenever a claim is checkable; (c) human confirms the final pick rather than auto-accepting the vote. These are testable design choices — ablating them is a paper result.

5. Verification Layer (the tie-breaker)

This is what makes AI4SE the right domain. For each stage we define a concrete, automatable check:

StageVerifiable signal
Gap-findingclaim grounded in retrieved papers (citation exists & supports); novelty vs. corpus
Ideationfeasibility probe: can a minimal scaffold be generated & run?
Experiment-designspec compiles to a runnable harness; baselines named & available
Executioncode compiles, tests pass, metric vs. baseline (e.g., SWE-bench-style slice)
Writingevery claim traces to a result or a real citation (no orphan claims)

Runs in an isolated sandbox (containerized, no network by default, time/mem capped).

All inter-agent traffic is structured (Pydantic) — cheap to log, replay, and later score. 7. Tech stack & dependencies free OSS only · no paid SaaS

Dependency philosophy

Frameworks are mostly free OSS — the only real spend is LLM tokens, unavoidable regardless of stack. So the rule is: free OSS libraries where they save real work; hand-written code where token-control and paper-legibility matter. Avoid paid SaaS (LangSmith, AgentOps, hosted trackers) and heavyweight agent frameworks whose hidden prompting/retries silently inflate the token bill.

Language

Python 3.14 (floor >=3.12), fully async (debate = many concurrent provider calls).

Providers

Official first-party SDKs (openai, anthropic, google-genai) behind our own LLMProvider Protocol + a shared retry/cost helper. Smallest, most trustworthy supply chain (LiteLLM had repeated 2026 CVEs + a PyPI supply-chain compromise). LiteLLM remains a drop-in option if we ever need 10+ providers.

Orchestration

Hand-written (~few hundred lines async). The debate is our contribution — full control of phases/termination/anonymization/budget; no hidden token overhead. No LangGraph/AutoGen/CrewAI.

Contracts

Pydantic for messages + structured outputs.

Retrieval

Two providers behind RetrievalProvider: an LLM-maintained wiki (curated synthesis) + OpenAlex (pyalex/httpx, live discovery). See Knowledge Layer. No RAG framework.

CLI · Store

Typer CLI; SQLite + JSONL transcripts (also the eval data). Local logging only.

Sandbox incr 2

Docker SDK / subprocess for the feasibility check; no framework.

8. Cost & reliability controls

  • Token + $ budget per debate; hard ceiling aborts gracefully.
  • Prompt caching on shared context (corpus, rubric) across rounds.
  • Cost-aware routing: cheaper models for high-volume non-debate passes (wiki librarian, lint); the chosen frontier models for the debate seats.
  • Every provider call retried with backoff; a dead vendor degrades the panel rather than failing the run.

9. Build order (the vertical slice)

  1. Slice first: Provider Abstraction Layer + a 3-vendor debate on one stage — gap-finding → idea + critique. No sandbox yet; this is the cheapest test of "does heterogeneous debate beat a single model?"
  2. Add the Verifier as tie-breaker on the execution stage (the genuinely novel part).
  3. Generalize remaining lifecycle stages.
  4. Harden + design the eval (Step toward publishable system).
Forward link: the eval decides publishability

The architecture is built so the debate transcript + verifier signals are the measurement substrate. Primary outcome (decided — see Research Framing): AI4SE ideation quality with verifier-based feasibility, heterogeneous vs. cost-matched homogeneous panel.
