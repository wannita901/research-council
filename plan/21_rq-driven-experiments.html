Phase 7 · Implementation (v2)

RQ-driven Stage B — one experiment per research question + CSV results

Built 2026-06-09 · 118 tests green · a real paper has several RQs, not one script

Stage B used to run a single experiment.py with one METRIC. Real research is multiple experiments — typically one per research question. The proposal now carries research questions, Stage B runs one council loop per RQ, and results aggregate into a CSV.

1 · The proposal carries research questions

Candidate/CandidateDraft gained research_questions: [ResearchQuestion{id, question, plan, metrics}]. The propose prompt asks for 1–3 independently-runnable RQs; the council argues over them (_apply_revision can replace the RQ set; judges see them via anonymize). Candidate.numbered_rqs() assigns rq1, rq2, … and falls back to a single RQ synthesized from the overall plan when none were proposed — so single-experiment behavior is preserved.

2 · Stage B runs one loop per RQ

for each RQ:
  council loop (implement → run → review → revise)   ← the plan/18 loop, unchanged
  → ExperimentResult (code, metric, approvals, …)
per-RQ budget: each RQ gets its own usd allowance (budget_base = spend so far)

run_experiments(idea, rqs, coder, reviewers, sandbox, caps) reuses the same agents across RQs but enforces the cap on the marginal spend (spent − budget_base), so the budget scales per-RQ rather than being consumed by the first one.

3 · Artifacts — per-RQ folders + aggregated CSV

projects/<id>/experiment/
├── results.csv        rq_id, question, metric, value, feasible, approved, approvals, iterations, stopped_reason, backend
├── rq1/  experiment.py · log.txt · reviews.md · question.md
├── rq2/  …
└── …

The CSV is the analysis-friendly summary (sort/plot/load into the paper); each RQ folder keeps the code the council actually ran, its log, and the reviews. Stage C reads the per-RQ results: the writer reports results per RQ, and the results figure plots one labelled bar per RQ.

4 · Files

store/models.py (ResearchQuestion, research_questions on the proposal, numbered_rqs(), RQResult), debate/experimentation.py (run_experiments, write_experiments + CSV, per-RQ budget_base), debate/deliberation.py + debate/anonymize.py + agents/{agent_peer,stub_agent_peer}.py (propose/revise/judge over RQs), prompts/peer/propose.md, agents/writer.py + verify/figure.py (Stage C consumes per-RQ results), cli.py _run_stage_b. Tests: test_experimentation.py (multi-RQ loop + CSV), test_proposal.py (numbered_rqs + render).
