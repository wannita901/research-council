Deliberation Balance (Q2) + All Caps in mise

Built 2026-06-10 · 123 tests green · grilled

In the first live run one peer (Aiden/openai) sent 0 deliberation messages while Cathy sent 8 — even though Aiden proposed, scored, and made 37 tool calls. Root cause: a peer that returns kind="pass" (or burns its tool budget on search then finalizes tool-lessly to a weak pass) is silently skipped, and round-robin lets a verbose peer fill the space. Fix: guarantee every peer a voice, cap any one peer, and surface all the knobs.

1 · Mandatory opening + capped free-form

each ideation round:
  OPENING (turn 0): every peer MUST post one critique of a peer's proposal (≠ its own)
    - agentic (tools on, per-agent budget); a 'pass' is coerced into a real critique
    - enforced via a must-critique finalizer (peer/finalize_critique.md) + coerce fallback
  FREE-FORM (turns 1..max_turns): organic answer / defend / revise / critique
    - per-peer message cap (incl. the opening); a peer muted once it hits the cap
    - converges when a turn adds nothing and no open questions remain
DecisionLocked value
Participationmandatory opening critique per peer (free target ≠ self) + free-form after
Per-peer cap3 / peer / round (1 opening + ≤2 free-form) → ≤9 msgs/round, evenly split
Opening mechanismagentic (tools allowed, per-agent cap) + must-critique finalizer; coerce pass→critique so no peer is ever silent
Tool budgetalready per-agent / per-call (no sharing, no starvation) — confirmed, unchanged

2 · Code

debate/deliberation.py — run_deliberation gains the opening pass + max_msgs_per_peer + coerce-on-pass; deliberate(..., require_critique=…) on the peer protocol. agents/agent_peer.py — _capped takes a finalize_prompt; deliberate(require_critique=True) uses an opening prompt + peer/finalize_critique.md. agents/stub_agent_peer.py — honors require_critique; free-form keyed on a prior revise (not "spoke at all") so the opening doesn't suppress it. RunConfig.max_msgs_per_peer threaded through run_ideation.

3 · All caps surfaced to mise

RC_PROFILE is the main Stage-B/C knob; every individual cap is overridable via env and shown (commented) in mise.toml. Precedence: per-field env > profile > code default; resolved at call time so RC_PROFILE in mise takes effect and --profile still overrides.
