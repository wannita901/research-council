UI Design Samples

Drafted 2026-06-08 · static mockups, no backend · the same fake run rendered 22 ways across 5 parts

Pick a direction (or a mix). Every sample shows the same ideation run — three peers (Aiden/Cathy/Julien) mid-debate, a ranking, the review gate, the live cost — so the only thing changing is the design.

  • Part 1 · skins (1–6) — one "council table" web layout, formal → weird.
  • Part 2 · structures (7–12) — different metaphors: chat, messaging, pixel-game, SaaS, board, canvas.
  • Part 3 · out-there (13–17) — war room, newspaper, terminal multiplexer, radio show, card battle.
  • Part 4 · lifecycle-framed (18–19) — the whole A→B→C journey as the frame (metro map, quest map).
  • Part 5 · blends (20–22) — score cards inside a chat / terminal, plus the recommended flagship.

How to read this
These are CSS mockups, not wired to the backend yet. Layout here is the simple "council table" (3 seats → deliberation → ranking → gate); we can apply your chosen taste to any layout from the previous step.
▶ Clickable prototypes
Two of these are built as interactive static prototypes (no backend — a simulated run you can replay, working gate buttons, and the macro-lifecycle navigation). Open them in a browser:
  • proto-flagship.html — #22 Flagship (console + lifecycle rail + persona seats + score cards)
  • proto-chat.html — #20 Group Chat (Discord + stat-card embed; lifecycle = channels)
  • proto-index.html — chooser linking both
Let each play, then click iterate/amend/conclude/select — select advances the lifecycle. (Open via a local server or directly; they're pure static.)

Picking a direction

You can also blend: e.g. the Research Console shell with Persona-colored seats (serious but characterful), or Academic styling reserved for the Stage-C writing view while ideation uses the Console. Tell me:

  • which sample (or blend) feels right,
  • light or dark default (most support a toggle),
  • how much motion (calm ↔ lively),

…and I'll write the detailed UI spec + build a clickable static prototype (still no backend) of the full run view in that style, then wire it to the SSE.
