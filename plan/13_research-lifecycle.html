Macro Lifecycle — The 3 Research Stages

2026-06-06 · The ultimate goal is a paper · The council loop is the engine inside each stage

The product runs a research project end to end toward a submittable paper, through three human-gated stages. The agentic council loop is the engine reused in every stage — but its shape changes: Ideation is a debate (compete for the best idea); Experimentation and Writing are collaboration (cooperate to build/verify, then to draft/review).

Cross-cutting: onboarding, gates, memory

  • Clarifying-question onboarding opens the project and each stage — a dedicated facilitator agent (separate from the council, cheap model) asks the human to set constraints before working (e.g. before Ideation: area, success criteria, compute/data limits; before Writing: target venue → drives scaffold-paper --class/--venue). (Council-generated questions are a documented alternative — plan/15 #5.)
  • Human approval gates between stages (A→B→C). Plus the within-loop review gate (iterate/amend/conclude/select) from the council loop.
  • Memory carries across stages: Ideation's plan feeds Experimentation; results feed Writing. Two tiers — within-project (trace/notes) + the long-term LLM-Wiki.

A · Ideation

The canonical debate (plan/12): peers research independently (agentic, tools), propose ideas, deliberate (critique novelty/feasibility/soundness, ground claims), and judge → a recommended research plan. Output is what you approve to take into experimentation.

B · Experimentation

The loop flips from competing to cooperating toward a shared goal. Peers decompose the plan, implement code, prepare data, run experiments, and review each other's code + tests. Here "critique" = code review / soundness validation, and "judge" = did we hit the experiment goal & are the results sound. This is where the deferred sandbox "run it" verification lives (real execution, tests, metrics) — plus fallback plans when an experiment fails.

C · Paper writing

Starts by asking the target venue, then runs scaffold-paper.sh --class <acmart|ieeetran|elsarticle|article> --venue … to lay down the LaTeX project. Peers co-author the sections (incl. figure plots from Stage B results), then switch to reviewer mode: critique the draft against that venue's acceptance criteria (novelty/soundness/evaluation/clarity/threats) and iterate until submission-ready.

Open specifics

  • Experimentation collaboration model: shared-artifact + reviewers vs role split (implementer / reviewer / tester) vs task-claiming.
  • How much Stage-A/B artifact context to carry into the next stage (full vs summarized).
  • Where the project's "state machine" lives (relates to the framework choice — see chat / next page).
  • Venue rubric source: curated per-venue checklists vs the council deriving them.
