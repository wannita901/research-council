Phase 7 · Implementation (v2)

Stage B & C — Council Collaboration Loops

Designed 2026-06-09 (grilled) · upgrades the single-shot Stage B/C in 13 to capped, multi-agent iterate-until-good loops · extends 15 #11/#12

v0 Stage B was one coder + retry; v0 Stage C was one writer + one reviewer. Both are now council loops: the 3 cross-vendor peers (Aiden/Cathy/Julien) collaborate to implement→run→review (B) and draft→review→improve (C), iterating until a real quality bar is met — and token-capped so they can't run away. Both still end at the existing human gate (awaiting_approval) and feed the next stage via StageHandoff.

1 · Stage B — experimentation loop author + reviewers

One peer implements; the other two cross-vendor peers review the code and the result; the author revises; re-run. Roles rotate per round so no single vendor is always the author.

iter 2: re-run → re-review → ... until (feasible AND K approvals) or cap

2 · Stage C — writing loop lead writer + PC reviewers

One peer is lead author and drafts the whole paper in markdown (cheap to iterate); the other two act as a venue program committee — score each rubric criterion 0–1 and file change-requests tagged by section; the lead revises only the touched sections; re-review. LaTeX is the export at the very end.

3 · LaTeX build-verify-fix tool "compiles clean" = the METRIC of writing

Mirrors the Docker sandbox for code. Runs once on the accepted draft (not every revision) so the costly compile stays out of the inner loop.

accept markdown paper
 → scaffold .tex from venue doc_class (acmart/ieeetran/article) via scripts/scaffold-paper
 → tectonic compile  (single self-contained binary; fetches packages on demand; reproducible)
      error / overfull-hbox?  → fixer agent patches .tex → recompile   (cap ~3, own usd sub-budget)
 → paper.pdf + build.log
no tectonic/latexmk on machine → emit .tex + warning, DON'T hard-fail   (mirrors build_sandbox refusal pattern)
Why a build tool (not just export)
The /insights report flagged recurring LaTeX/bibtex build failures (incl. a self-referential @-in-comment bug). Treating "compiles clean" as a verifiable gate — like "ran + emitted METRIC" — is exactly the verification-backed discipline that worked best in past sessions. Tectonic avoids the fragile system-TeX dependency.

4 · Token bounding (the explicit ask)

  • Per-stage USD budget guard: a meter sums peer usage after each agent turn; when it would exceed usd_budget, the loop stops and returns best-so-far (no partial half-turn).
  • Hard iteration cap (max_iters / max_revisions) independent of budget — whichever binds first wins.
  • Verification probes and the LaTeX fixer have their own small sub-caps so they can't blow the stage budget.
  • All caps overridable per-run; the three profiles (Conservative/Balanced/Thorough) are presets.

6 · Build order

  1. Contracts in models.py (findings, reviews, change-requests, venue intake, extended results).
  2. Stage B loop: CodeReviewer + coder revise + rewrite run_experimentation (budget guard, K-of-N, probes). Offline tests.
  3. Stage C loop: reviewer change-requests + scores, lead targeted revise + coherence, rewrite run_writing (accept bar, budget). Offline tests.
  4. LaTeX: verify/latex.py + latex_fixer + figure render; wire as the post-accept export. Tectonic-optional tests.
  5. Venue intake (recommend+confirm) + CLI profiles wiring. mise run test green.

Built 2026-06-09 (v0, 110 tests green). As-shipped notes vs the design above:

  • Figure: rendered host-side from the real METRIC by trusted code (verify/figure.py, matplotlib as a soft dependency — no figure if it's absent, never a crash). This sidesteps needing the sandbox to return a PNG artifact.
  • LaTeX fix loop: v0 is mechanical — special-char escaping (kills the @/&/_ class of bugs at the source), inline thebibliography instead of bibtex, and a doc-class→article fallback on failure. An LLM latex-fixer agent is the obvious next upgrade.
  • Citations: grounded-only is wired (grounded_citations() reads the wiki's origin:external pages; the writer drops any key it wasn't handed). Search-augmentation is deferred.
  • Role rotation: author/lead is fixed within a single stage run (keeps the author's context) — cross-run rotation deferred.

Deferred: section co-authoring · competitive drafts · LLM latex-fixer · web-search citation verification · multi-file experiment repos (single script for now).
