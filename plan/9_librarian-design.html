The librarian is the agent that maintains the wiki: it ingests sources, routes content into typed pages, cross-links, and lints. Locked decisions: Claude Sonnet for all passes, hybrid merge gate, and the expanded AI4SE taxonomy below. The hard part is routing — the page types overlap unless defined sharply, so this page nails the definitions.

1. Page taxonomy (final)

FolderHolds — the question it answersDoes NOT hold
papers/One note per source — the anchor that links out to every typed page the paper touchesDeep synthesis (that lives in the typed pages)
tasks/WHAT problem — the SE goal addressed (program repair, flaky-test detection)Any technique or evaluation
motivations/WHY — why the problem matters, why a design choice was made, assumptions, pain pointsWhat was built or how it was tested
concepts/The IDEA — SE philosophy, framing, theory, principles (e.g. "tests as specification")Concrete algorithms or study protocols
approaches/HOW (technical) — the technique / architecture / algorithm a paper builds (e.g. "agentic repair with execution feedback")How it was evaluated; the abstract idea behind it
methods/HOW (validated) — research methodology: study design, baselines, datasets/metrics, statistics, threatsThe technique itself; the motivation
benchmarks/The datasets / benchmarks themselves (SWE-bench, Defects4J): size, metrics, caveatsResults obtained on them (those are findings)
findings/WHAT was found — results / claims, cross-paper, each with evidence refsUnsupported opinion
gaps/What's missing — open problems, unaddressed motivations, weak methods → feeds ideationSolved problems

Plus index.md (catalog) and log.md (ingest/lint history). Folder names are cosmetic and renameable.

The disambiguation that keeps routing clean

approaches = the thing they built · methods = what they did to validate it · concepts = the idea underneath · motivations = the why. These four go in the librarian's schema prompt verbatim so Sonnet routes consistently.

Worked example — one paper fans out

"Agentic program repair with execution feedback, evaluated on SWE-bench via pass@k with ablations" ingests into:

papers/doe-2025-agentic-repair.md        # anchor → links to all below
  ├─ tasks/program-repair.md             # the problem
  ├─ motivations/why-execution-feedback.md   # why feedback should help
  ├─ concepts/tests-as-oracle.md         # the underlying idea
  ├─ approaches/agentic-repair-exec-feedback.md   # the technique built
  ├─ methods/passk-with-ablations.md     # how it was evaluated
  ├─ benchmarks/swe-bench.md             # the dataset
  ├─ findings/exec-feedback-improves-repair.md    # the result
  └─ gaps/repair-beyond-test-passing.md  # open problem it exposes

2. Page schema (default — iterable)

Every page is markdown with YAML frontmatter; required sections vary by type. Example for an approaches/ page:

---
type: approach
title: Agentic repair with execution feedback
papers: [doe-2025]                 # citation keys → raw/external only
related: ["[[task:program-repair]]", "[[method:passk-with-ablations]]"]
updated: 2026-06-04
---
## Summary           # 2–3 sentences
## How it works      # the mechanism
## Evidence          # claims w/ paper refs
## Contradictions / open questions

3. Ingest pipeline (the librarian's loop)

council ingest <source>:
  1 load + SANITIZE      # untrusted input: strip injected instructions; treat as data
  2 extract → papers/    # create the anchor note
  3 route + synthesize   # create/update the typed pages (tasks/approaches/methods/…),
                         #   add cross-links + citation refs back to raw/external
  4 dedup               # source hash + title similarity → merge, don't duplicate
  5 lint                # contradictions, orphans, schema violations, stale claims
  6 gate (hybrid)       # clean → auto-merge ; flagged → human review diff
  7 commit (transactional) → append log.md → record wiki commit hash

When does ingest fire? — triggers & timing

Ingestion is always offline and after a debate (or on demand) — never in the debate hot path. A debate reads a committed snapshot; papers discovered mid-debate are read transiently, not written. v0 triggers:

  • Manual — council ingest <path>: papers you add yourself. Always on.
  • Post-debate harvest (opt-in) — after a debate ends, the external (OpenAlex) papers the peers discovered are queued and ingested into raw/external/, so the wiki compounds from use. Runs through the hybrid gate like any ingest.
  • Eval freeze (non-negotiable) — during an experiment batch the wiki is frozen (auto-harvest OFF) so runs stay comparable; the wiki commit hash is pinned in every run trace.
  • Deferred: watch-folder / scheduled ingest.

The debate's own outputs go to raw/internal/ and are never harvested as prior art — the self-contamination rule from the Knowledge Layer.

The read ↔ write lifecycle

How the read and write sides interleave across debates — the wiki compounds only between runs, and only from real literature:

      ┌───────────────────────────────────────────────────┐
      │                                                     │
      ▼                                                     │
  [ wiki snapshot @ commit C ]                              │
      │  READ (Phase 1: peers consult synthesized pages)    │
      ▼                                                     │
  DEBATE ──► peers discover external papers via OpenAlex    │
      │       (transient READ only — no write mid-run)      │
      ▼  debate ends                                        │
  harvest queue ── external / OpenAlex finds ONLY           │
      │  (opt-in · OFF during eval freeze)                  │
      ▼                                                     │
  LIBRARIAN ingest (offline · Sonnet)                       │
      │  route → dedup → lint → hybrid gate                 │
      ▼                                                     │
  commit C+1  (transactional · log.md · hash → run trace) ──┘
      │
      ▼
  next debate READS the grown snapshot @ C+1

  the council's own ideas/critiques ─► raw/internal/
                                       (never harvested as prior art)

Key invariants: the wiki is immutable within a debate; it only advances (C → C+1) via an offline, gated ingest between debates; every debate's result is tied to the exact snapshot it read.

4. Model & merge — locked

Librarian model

Claude Sonnet for all passes (ingest synthesis + lint). Balanced quality/cost; batch + budget-cap the high-volume passes. Offline, so it never inflates per-debate cost. Swappable later (e.g. Haiku for lint) if cost bites.

Merge gate — hybrid

Stage edits on a git branch → schema-validate + lint. Clean & no contradiction → auto-merge; contradiction or low-confidence → pause for your review diff. Every change git-revertible.

5. Defaults we can iterate

  • Trigger: manual council ingest + opt-in post-debate harvest (external-only, gated, frozen during eval) — see "When does ingest fire?" above; watch-folder deferred.
  • Identity & links: kebab-case slugs; [[type:slug]] wikilinks; dedup by source hash + title similarity.
  • Peer search over the wiki: index.md navigation + BM25 now; add embeddings only if recall suffers.
  • Lint cadence: every ingest, plus on-demand council lint.

6. Where it lives (write side)

research_council/
  librarian/   agent.py       # the Sonnet maintainer (model + prompts)
               ingest.py      # the pipeline above
               router.py      # content → typed page (uses the schema prompt)
               lint.py        # checks + hybrid gate
               schema.py      # frontmatter + per-type section contracts
  retrieval/   wiki.py        # read side — peers query the wiki
  config/      wiki.yaml      # model: sonnet · gate: hybrid · taxonomy: [...]
Open to iterate

Taxonomy, schema, and routing definitions are the parts most likely to shift once we ingest real papers and see what mis-files. They live in one place (wiki.yaml + the schema prompt), so iterating is a config/prompt change, not a code rewrite.
