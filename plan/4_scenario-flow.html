Debate Flow Walkthrough

Updated 2026-06-04 · The concrete run, as described · Click a phase for detail

This is the scenario in motion: you propose a topic; three peer agents (one per vendor) research independently, then convene to cross-critique, rebut, verify, and vote; you confirm the result. Click each phase below.

🟢 OpenAI seat 🟣 Claude seat 🔵 Gemini seat 🧑 You (human-in-the-loop)
0
IntakeYou ask a question / propose a topichuman
You enter a research question or topic (e.g. "Are LLM code-review agents better at finding security bugs than static analyzers?"). The system selects the stage (gap-finding, ideation, …) and the 3 vendor seats for this run.
1
Research · parallelEach peer investigates on its own3 peers, concurrent
All three peers work independently and in parallel, each with retrieval-tool access (Hybrid/OpenAlex + local index). Each forms its own grounded view of the literature — no cross-talk yet, so the three perspectives stay genuinely diverse.
2
ProposeEach peer puts forward one candidate3 peers
Each peer submits a single grounded candidate (a gap / idea / plan), with evidence references. Now there are three candidates on the table, each carrying its own citations.
3
Cross-critiquePeers critique each other3 peers, anonymized
Every peer critiques the other two on soundness, novelty, feasibility, citing evidence or flagging a claim for verification. Authorship is anonymized so no peer knows which candidate is its own — the core self-preference-bias control.
4
Rebut / reviseAuthors defend or revise3 peers
Each candidate's author responds to critiques — conceding, defending with evidence, or revising the candidate. Disagreements that hinge on a checkable fact are pushed to the verifier.
5
VerifySandbox settles checkable claimsverifier (tool)
The verifier runs the stage's concrete check (citation exists & supports; scaffold runs; tests pass; metric vs. baseline) in an isolated sandbox. This ground-truth signal outweighs opinion — rhetoric cannot beat a failing build.
6
Judge · loopAnonymized panel vote → recommendation3 peers
Peers score all candidates (authorship hidden); the verifier signal weights the scores into a ranked recommendation. If no termination rule has fired, the debate loops back to phase 3 with the revised candidates.
✓
ConfirmYou make the final callhuman
You see the ranked candidates, the verifier evidence, and the full debate transcript, then confirm / pick / send back for another round. The whole run is checkpointed, so you can stop and resume anytime.

About the UI (deferred, kept in mind)

UX / UI is its own step later

For v0 this runs as a checkpointed CLI. We will design the front-end / UX as a dedicated step. Architecturally it already fits: the orchestrator is a runner-agnostic async generator that yields each phase's result, so a UI simply subscribes to that stream — the diagram above is essentially the screen we'd build (live per-phase progress + the transcript + a confirm control). No rework needed to add it.

What this confirmed / changed in the plan

  • Added an explicit independent parallel research phase (phase 1) before peers convene — keeps the three perspectives diverse.
  • Changed the panel from fixed roles (Proposer/Critic/Judge) to 3 symmetric peers, each proposing and critiquing — matches the described scenario. Updated in Architecture §3–4 and Decisions Q1–Q2.
  • Confirmed judging = anonymized panel vote, verifier-weighted, human confirms (Decisions).
  • Noted UI as a future step; architecture already supports streaming to it.
