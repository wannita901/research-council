Phase 7 · Implementation (v2)

Research Proposal as the Stage-A Artifact + the Evidence Rule

Built 2026-06-09 · 114 tests green · three asks: rename onboarding · proposal artifact · cite/evidence everywhere

Three refinements that sharpen what the council actually produces and the rigor it holds itself to.

1 · "intake" → "onboarding"

The front-door clarifying-question step is now called onboarding everywhere (user-facing + code). Renamed symbols: OnboardingQuestion(s), run_onboarding, the trace phase onboarding, the prompt facilitator/onboarding.md, CLI labels. The distinct Stage-C venue step was renamed VenueChoice/_venue_choice (it's selection, not onboarding) so the word "intake" is gone entirely.

2 · Stage A produces a full research proposal (not a title)

The council now argues over a complete proposal. Candidate/CandidateDraft gained problem_statement, motivation, dataset_metrics, fallback_plan (alongside the existing title/hypothesis/method/experiment_plan/gap). The full shape:

Proposal fieldNote
Titlespecific, informative
Problem Statementthe concrete problem
Motivationwhy it matters / impact
Hypothesisthe testable claim
Proposed Methodthe approach, implementable
Step-by-step Experiment Plannumbered steps from smallest runnable step up; named baselines
Dataset / Metricsdata + the metric(s) that confirm/refute the hypothesis
Fallback Planwhat to do if the main plan fails, so the project still yields a result
  • Argued over: _apply_revision now patches any proposal field during deliberation; the propose prompt asks for all fields; judges score the full proposal (anonymize exposes every field, authorship still hidden).
  • Saved as an artifact: projects/<id>/proposal.md (via Candidate.as_proposal_md()), recorded on the ideation stage and printed at the gate.
  • Flows downstream: the whole proposal rides StageHandoff.idea → Stage B's coder implements the plan (METRIC = a proposal metric; sees dataset/fallback) → Stage C's writer drafts from both the proposal and the experiment result.

3 · Evidence rule — every claim cites a reference or shows evidence, always

Baked into the prompts and enforced by the reviewers at every stage:

WhereRule
peer/proposeevery factual claim (esp. problem/motivation) cites a brief reference [ref-id], or is restated as an explicit assumption — never an unsupported assertion.
peer/deliberatepeers challenge any uncited claim — ask for the reference or push to soften it; cite when defending/revising.
writing/writerevery nontrivial claim is backed by a citation or the experiment ("in our run, f1=0.62"); every number traces to the metric/log.
writing/reviewerfiles a HIGH-severity (blocking) change-request for ANY claim or result lacking a citation/evidence.
Stage Ba "result" already needs evidence by construction: it must run and emit a METRIC, with reviewer verification probes as backing.
