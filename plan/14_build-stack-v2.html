Build Stack v2 — Frameworks Decision

2026-06-06 · Minimal now, swappable later · Cross-vendor is non-negotiable

Now that we're product-first and agentic, we add frameworks surgically — only where they remove real toil — and keep clean interfaces so any layer swaps later. The single-vendor agent SDKs (OpenAI / Claude) are ruled out as the brain because cross-vendor is our identity; they can still be stage-scoped muscle.

Stage B sandbox — Docker (no SDK, MCP later)

  • Docker = the experiment sandbox. One container per experiment; mounted workdir; CPU/mem/timeout caps; network only during a controlled dataset-fetch step. This is the deferred "run-it" verification, scoped to Stage B.
  • No agent SDK. "Agent with a computer" = a few tools (run_in_docker, read/write_file, run_tests) any peer can call. The Claude Agent SDK does this well but is Claude-only + heavier — against minimal/cross-vendor.
  • MCP = optional, later. Community shell/fs/git/code-exec MCP servers could be reused, but they add server lifecycle + protocol overhead. Direct Docker tools are simpler now; revisit MCP to reuse servers or expose our tools to other agents.

Flexibility = clean seams (the "switch later" guarantee)

Each layer sits behind a Protocol/interface; swapping an implementation is local. Stable seams:

LLMProvider        vendor calls            (ours → LiteLLM)
Peer / Agent       the reasoning+tool loop (PydanticAI → hand-rolled/LangGraph)
Tool               a callable capability   (retrieval, docker-exec, …)
RetrievalProvider  a kind of Tool          (ours → MCP)
Verifier           grounding / sandbox     (mock → Docker)
Runner             CLI · service           (already runner-agnostic)
Checkpoint/Store   persistence             (JSONL → LangGraph/DB)

What changes vs what stays

Adopt now

PydanticAI for the agentic peers (research/deliberate/propose). Docker tool for Stage B.

Keep

Provider layer, retrieval adapters (wrapped as tools), hand-written orchestrator (extend for deliberation + stages + round re-entry), FastAPI backend, CLI, wiki, trace.

Defer (revisit triggers)

LangGraph → when cross-session resume hurts. MCP → to reuse servers / expose tools. Claude Agent SDK → not planned (cross-vendor + minimal).

Updates earlier guidance

This relaxes the v1 "no agent framework in core" rule (plan/2 §7): we now use PydanticAI as a lightweight agent/tool-call lib, while orchestration stays hand-written — so the minimal-core spirit holds. Determinism/eval-first are already dropped (plan/12).
